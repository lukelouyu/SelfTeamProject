Getting started
Run the JAR, enter guide when needed, and use bye to exit.
Related commands: guide, bye

Enter guide to see the numbered menu, then either type a number
such as 2 or go straight to a topic by name, for example guide add.

Examples:
  guide
  guide 2
  guide add
  bye

Add activities
Use add with FIXED timing or a FLEXIBLE window and duration.
Related commands: topic add, list, view

Replace the description, date, times, and ratings below with
your own values.

Example - add a fixed activity:
  add n/PL1101E Lecture c/ACADEMIC date/YYYY-MM-DD type/FIXED from/09:00 to/11:00 energy/1 sensory/1 note/Bring laptop and charger

Example - add a flexible activity:
  add n/Finish assignment c/ACADEMIC date/YYYY-MM-DD type/FLEXIBLE earliest/12:00 latest/18:00 dur/90 energy/4 sensory/2

Then view your activities:
  list
  list view/detail
  list date/YYYY-MM-DD

Optional - create and use a topic first:
  topic add c/ACADEMIC n/PL1101E
  add n/PL1101E Tutorial c/ACADEMIC date/YYYY-MM-DD type/FIXED from/10:00 to/11:00 energy/2 sensory/2 topic/PL1101E

Edit an activity
Format: edit ID PREFIX/NEW_VALUE [PREFIX/NEW_VALUE ...]
Any subset of fields may be supplied, in any order. Stable IDs never
change. Every change is validated before the y/n prompt is shown.

Example - list first, then edit one field:
  list
  edit 3 energy/5

Example - change several fields at once:
  edit 3 n/CG3207 tutorial date/YYYY-MM-DD topic/CG3207

Example - change a fixed activity's time:
  edit 3 from/14:00 to/15:00

Example - clear an existing note:
  edit 3 note/

After reviewing the before/after summary, answer y to save or n to
cancel (anything other than y is treated as n).

Find activities
Format: find [today|tomorrow|this week|next week] [k/KEYWORD ...] [FILTERS]
Multiple keywords and filters use AND. k/ accepts one or two
words; three or more words is rejected. An optional leading
today/tomorrow/this week/next week phrase works the same as in
list, and cannot be combined with date/.

Examples:
  find k/PL1101E
  find k/lecture
  find c/ACADEMIC
  find date/YYYY-MM-DD
  find today
  find next week c/ACADEMIC
  find k/PL1101E c/ACADEMIC
  find k/finish assignment order/time

Example - checking when nothing matches:
  find k/nonexistentkeyword12345

Every supplied keyword and filter must match. Search is
case-insensitive and can match part of a word.

Categories and topics
Topics are optional one-level groupings inside fixed categories.
Related commands: topic add, topic list, topic rename, topic delete

Example - create and use a topic:
  topic add c/ACADEMIC n/PL1101E
  topic list c/ACADEMIC
  add n/PL1101E Lecture c/ACADEMIC date/YYYY-MM-DD type/FIXED from/09:00 to/11:00 energy/1 sensory/1 topic/PL1101E

Example - rename a topic:
  topic rename c/ACADEMIC old/PL1101E new/PL1101E Revision

Renaming asks for y or n before saving, and updates every
activity already using the old topic name.

Example - delete an unused topic:
  topic delete c/ACADEMIC n/Unused Topic

A topic cannot be deleted while any activity is still using it.

Data files and storage
Application data (activities, topics, your saved default order, and
global planning preferences)
is stored under data/. Do not edit data files while the application runs.

data/academic-calendar.txt is different: it is a reference file you or
your school maintains yourself, only read by recur (see guide recur),
loaded once per run the first time you use recur, and never created,
repaired, or changed by UniEnable itself - including by reset all.

Dashboard: a planning-load summary
Format: dashboard today|tomorrow|date/YYYY-MM-DD|day/YYYY-MM-DD|this week|next week [detail]
Related commands: completion (see guide completion for mark/unmark/list status/)

Shows how much is planned for a period, how much room is left, how
energy/sensory-demanding it is, and how much of what's already due is
complete - using only activity data you already entered. this week
means Monday through Sunday of the current week, the same as list
this week; next week is the following Monday-Sunday week. detail adds
fixed/flexible counts, a category breakdown, and the full 1-to-5
energy/sensory rating distribution. date/ and day/ are interchangeable -
use whichever you remember; timetable accepts the same pair.

Examples:
  dashboard today
  dashboard tomorrow detail
  dashboard date/YYYY-MM-DD
  dashboard day/YYYY-MM-DD
  dashboard this week detail
  dashboard next week

"Nominal buffer" is arithmetic capacity minus planned workload - not
a promise that time is actually free or usable. Energy and sensory
numbers are shown exactly as you entered them, as planning data only,
never as a medical or performance judgement.

Text timetable
Format: timetable today|tomorrow [detail]
        timetable day/YYYY-MM-DD [detail]
        timetable date/YYYY-MM-DD [detail]
        timetable week/YYYY-MM-DD [compact|detail]
        timetable this week [compact|detail]
        timetable next week [compact|detail]

Shows fixed activities in chronological day sections. today/tomorrow are
shorthand for day/ with the current/next date; date/ is an interchangeable
alias for day/ - use whichever you remember, dashboard accepts the same
pair. Weekly views cover Monday through Sunday; next week is the
following Monday-Sunday week. Flexible activities stay in a separate
unscheduled section with their window and required duration; no time is
invented for them. compact omits empty days for narrow terminals, while
detail adds completion, category, rating, topic, and note information.

Examples:
  timetable today
  timetable day/YYYY-MM-DD
  timetable day/YYYY-MM-DD detail
  timetable date/YYYY-MM-DD
  timetable week/YYYY-MM-DD compact
  timetable this week detail
  timetable next week

Timetable is read-only. It does not schedule flexible activities, create
recommendations, infer buffers, or change any stored data.

Global planning preferences
Format: preference view
        preference set start/HH:mm [end/HH:mm] [buffer/MINUTES] [tomato/on|off]
        preference reset

Stores one global profile that the recommend command reads (see guide
recommend). Fields supplied to preference set may appear in any order;
omitted fields retain their current values. start must be before end,
buffer must be from 0 to 1440 minutes, and tomato controls advisory
Tomato/Pomodoro suggestions only.

start/end are a hard boundary on recommend's scheduling window, not just
a preference it tries to honour - see guide recommend for the exact rule.

Defaults: start 08:00, end 20:00, buffer 15 minutes, tomato off.

Examples:
  preference view
  preference set start/07:30 end/21:00 buffer/20 tomato/on
  preference set tomato/off
  preference reset

Changes and reset require y/n confirmation. These settings are the
planning inputs for recommend: start/end and buffer are enforced as hard
scheduling constraints, and Tomato only affects advisory study
suggestions, not slot generation or activity timing.

Flexible activities already adopted from a recommendation keep their
existing scheduled times - a preference change never moves them; it only
affects future recommend proposals. An existing unadopted proposal is also
unaffected until you act on it: recommend adopt re-checks it against your
current preferences and rejects it if they no longer fit (see guide
recommend).

Recommended timetable
Format: recommend
        recommend this week
        recommend next week
        recommend today
        recommend tomorrow
        recommend date/YYYY-MM-DD
        recommend day/YYYY-MM-DD
        recommend view
        recommend adopt
        recommend cancel

recommend and recommend this week generate one deterministic weekly
preview for incomplete flexible activities; recommend next week does the
same for the following Monday-Sunday week. recommend today/tomorrow are
shorthand for recommend date/ with the current/next date; recommend
date/YYYY-MM-DD (or its recommend day/YYYY-MM-DD alias) generates a
one-day preview for any date not before today. recommend view re-shows
the current proposal, recommend adopt
confirms and saves it once, and recommend cancel discards it with no
change.

The recommender uses fixed activities, flexible windows, and your
global planning preferences. Preferred daily start/end is a hard
boundary - a placement is never proposed outside it, even partly, and
an activity with no compliant slot inside it is left unscheduled.
Minimum buffer is enforced; Tomato only adds advisory study
suggestions when enabled. Activities keep their stable IDs and
original flexible windows.

No proposed start is ever before the current time. A today window that
has already fully elapsed is left unscheduled rather than backdated; a
partly elapsed today window starts at the next whole minute from now.
recommend adopt is rejected as stale if any proposed start has already
passed since the proposal was generated - regenerate with recommend.
recommend adopt is also rejected if start/end preferences changed since
generation and no longer contain one or more proposed placements -
regenerate with recommend to pick up the new preferences.

Examples:
  recommend
  recommend this week
  recommend next week
  recommend today
  recommend date/YYYY-MM-DD
  recommend day/YYYY-MM-DD
  recommend view
  recommend adopt

Limitations: recommendation does not use route/facility data yet,
because activities still do not store facility/location bindings.

Accessible routes
Format: route from/FACILITY to/FACILITY
Related commands: facility (see guide facility), connection (see guide connection)

Finds the shortest route between two known facilities using only connections
confirmed accessible (status YES) - connections marked NO or unknown are never
used, even as a last resort. from/ and to/ may appear in either order.

Examples:
  route from/AS6 to/AS8
  route from/CLB to/AS7
  route from/AS1 to/AS1

The source and destination being the same facility is a valid result: a
single-facility route with 0 m total distance, not an error.

Limitations: this does not estimate travel time, and does not guarantee
real-world accessibility at the time of travel - only that the local dataset
records a confirmed-accessible path. If no confirmed-accessible path connects
two known facilities, route says so rather than suggesting an unconfirmed one.

Sample local accessibility reference data. Distances are estimates and may be incomplete. Please verify with current campus information when needed.

Reset all user data
Format: reset all
Shows a preview (how many activities, class schedules, and topics
exist) and a menu with three explicit choices - nothing is deleted
until you pick one. This cannot be undone.
Facility, connection, and academic-calendar reference data is
always kept, whichever choice you pick.

Choices:
  [1] Delete all user data - every activity and topic is cleared,
      saved default order and preference profile reset to defaults, and the
      next activity ID restarts at [1].
  [2] Delete other activities but keep class schedules - keeps
      every fixed lecture/tutorial/lab/section-teaching activity
      (the same activities recur can build on - see guide recur)
      with its original ID, note, and completion status, deletes
      everything else, and keeps only the topics still used by a
      kept activity. Your preference profile is retained.
  [3] Do not delete anything - cancels with no change.

Example:
  reset all
  2

Entering anything other than 1, 2, or 3 (including a blank line)
cancels safely with no change.

Create recurring class sessions
Format: recur TASK_ID week WEEK_SPEC
WEEK_SPEC is one or more week numbers or inclusive ranges, separated
by semicolons, for example "1 to 6; 7 to 13" or "3;7;9;11". Week
numbers refer to the external data/academic-calendar.txt file, not a
fixed maximum - ask whoever maintains that file if a week you expect
is missing.

Only a FIXED activity in the ACADEMIC category whose description
contains lecture, lec, tutorial, tut, lab, laboratory, section
teaching, sectional teaching, or sec is eligible (see guide reset
for the same rule used by reset's "keep class schedules" choice).

Example:
  add n/CG3207 Lecture c/ACADEMIC date/YYYY-MM-DD type/FIXED from/16:00 to/18:00 energy/2 sensory/2
  recur 1 week 1 to 6; 7 to 13

Each new session becomes its own independent activity with its own
ID - mark, unmark, edit, and delete only ever affect the one
occurrence you target, not the others. The original activity's own
week is always included automatically; you do not need to list it.

Before creating anything, a preview lists every date to be created
and every date skipped (already the source week, an identical
session that already exists, or a date with no classes in the
calendar file) and asks Continue? (y/n). Only y creates the
sessions; if a target date would overlap another activity's
occupied time (a fixed activity, or one already adopted from a
recommendation) or resolve to a date/time already in the past, the
whole command is rejected instead of creating a partial batch.
Running the same recur command again creates nothing new.

If data/academic-calendar.txt is missing or cannot be read, recur
reports the problem and every other command keeps working normally.

Application data (activities, topics, your saved default order, and
global planning preferences)
is stored under data/. Do not edit data files while the application runs.

data/academic-calendar.txt is different: it is a reference file you or
your school maintains yourself, only read by recur (see guide recur),
loaded once per run the first time you use recur, and never created,
repaired, or changed by UniEnable itself - including by reset all.

Accessible routes
Format: route from/FACILITY to/FACILITY
Related commands: facility (see guide facility), connection (see guide connection)

Finds the shortest route between two known facilities using only connections
confirmed accessible (status YES) - connections marked NO or unknown are never
used, even as a last resort. from/ and to/ may appear in either order.

Examples:
  route from/AS6 to/AS8
  route from/CLB to/AS7
  route from/AS1 to/AS1

The source and destination being the same facility is a valid result: a
single-facility route with 0 m total distance, not an error.

Limitations: this does not estimate travel time, and does not guarantee
real-world accessibility at the time of travel - only that the local dataset
records a confirmed-accessible path. If no confirmed-accessible path connects
two known facilities, route says so rather than suggesting an unconfirmed one.

Sample local accessibility reference data. Distances are estimates and may be incomplete. Please verify with current campus information when needed.

Text timetable
Format: timetable today|tomorrow [detail]
        timetable day/YYYY-MM-DD [detail]
        timetable date/YYYY-MM-DD [detail]
        timetable week/YYYY-MM-DD [compact|detail]
        timetable this week [compact|detail]
        timetable next week [compact|detail]

Shows fixed activities in chronological day sections. today/tomorrow are
shorthand for day/ with the current/next date; date/ is an interchangeable
alias for day/ - use whichever you remember, dashboard accepts the same
pair. Weekly views cover Monday through Sunday; next week is the
following Monday-Sunday week. Flexible activities stay in a separate
unscheduled section with their window and required duration; no time is
invented for them. compact omits empty days for narrow terminals, while
detail adds completion, category, rating, topic, and note information.

Examples:
  timetable today
  timetable day/YYYY-MM-DD
  timetable day/YYYY-MM-DD detail
  timetable date/YYYY-MM-DD
  timetable week/YYYY-MM-DD compact
  timetable this week detail
  timetable next week

Timetable is read-only. It does not schedule flexible activities, create
recommendations, infer buffers, or change any stored data.
